# Belief-Graph World Model — Text World Agent

Track 2: World Modeling for Autonomous Agents

An autonomous agent that explores a text adventure using an external, structured
world model instead of conversation history. The agent is a pure function of
`(objective, current_world_slice)` — it never sees its own past actions or
observations directly. All memory lives in a graph-based world model, which is
queried fresh at every step.

The standout feature is the **Contradiction Journal**: when the agent's beliefs
about the world are contradicted by new observations (e.g. a door believed
locked is later found open), the correction is detected, logged with full
detail, and resolved — rather than silently overwritten.

## Architecture
[Game] → [Extractor] → [Updater] → [World Model (graph)]
│
[Query Layer: get_slice()]
│
[Ollama LLM] → action → [Game]
(loop repeats)

- **Game** (`environment/game.py`) — a custom 5-room text adventure (Entrance
  Hall, Kitchen, Cellar, Study, Garden) with a locked door and a key, deliberately
  scripted to produce a real contradiction for the agent to catch and resolve.
- **Extractor** (`agent/extractor.py`) — parses the game's raw text responses
  into structured facts (rooms, connections, object states).
- **World Model** (`world_model/graph.py`) — a graph of rooms and objects, each
  fact carrying a confidence score and a last-updated step. Fully human-readable
  when saved to JSON.
- **Contradiction Journal** (`world_model/journal.py`) — logs every belief
  correction: old value, new value, when it was first believed, when it was
  corrected, and why.
- **Updater** (`agent/updater.py`) — writes extracted facts into the world model,
  routing conflicts through the journal.
- **Query Layer** (`WorldModel.get_slice()`) — builds a compact, relevant slice
  of the world model (current room + connections + objective-relevant facts)
  for the agent, rather than handing over the entire map every step.
- **Agent** (`agent/ollama_agent.py`) — a small local language model (Qwen2.5 3B
  via Ollama, CPU-only, no GPU/cloud API) that receives only the current slice
  and objective, and returns a single action.
- **Safety Check** (`main.py`) — a lightweight deterministic guardrail on top of
  the LLM's decision. Small local models don't always follow instructions
  perfectly; this catches known failure patterns (ignoring an item on the floor,
  ignoring a known key when a door is locked, repeating an already-visited exit)
  and corrects the action before it's sent to the game.

**No conversation history is ever passed to the LLM.** Each step, the prompt
contains only the current world slice and the objective — nothing else.

## Setup

**Requirements:** Python 3.10+, [Ollama](https://ollama.com) (runs models
locally, CPU-only, no GPU required).

```bash
# 1. Install Ollama, then pull the model
ollama pull qwen2.5:3b

# 2. Clone this repo and enter the project folder
git clone <your-repo-url>
cd track1-worldmodel

# 3. Create a virtual environment and install dependencies
python -m venv venv
venv\Scripts\activate        # Windows
# source venv/bin/activate   # macOS/Linux
pip install requests
```

## Running the agent

```bash
python main.py
```

This runs the full agent loop autonomously — no human input at any point. The
agent will:
1. Explore the map, tracking visited rooms to avoid pointless repetition
2. Discover the key in the Cellar and pick it up
3. Return to the Kitchen and unlock the door
4. **Trigger a genuine contradiction** the moment it discovers the door — which
   it previously believed was locked — is now open
5. Reach the Study, completing the objective

A typical successful run completes in around 8 steps, with exactly 1
contradiction detected and resolved.

### Output files (written to `logs/` after every run)

| File | Contents |
|---|---|
| `world_model_final.json` | The complete, final world model — every known room, connection, and object, with confidence scores. Fully human-readable. |
| `contradiction_journal.json` | Every belief correction made during the run: old value, new value, step numbers, and reason. |
| `run_trace.json` | A full step-by-step trace (room, action, game response, any contradiction) used by the map replay viewer. |

## Viewers

Two standalone HTML viewers are included in `viewer/` for visually inspecting a
completed run — no server required, just open the file:

- **`belief_graph_viewer.html`** — load `world_model_final.json` and
  `contradiction_journal.json` to see the final world state and the
  corrected-belief cards.
- **`map_replay.html`** — automatically loads the latest run's trace
  (`run_trace_data.js`, generated by `main.py`) and animates the agent walking
  through the map step by step, with a speech bubble showing each decision and
  a visual flash when a contradiction occurs. Use the Play/Next/Prev controls
  to step through the run.

## Design decisions

**Why a graph instead of a flat list/dictionary?** A graph structure mirrors
how spatial knowledge is actually held — rooms, connections, and objects as
distinct, related entities — and stays inspectable and human-readable even as
the explored world grows, directly answering the brief's requirement that the
world model be "consistent, queryable, and does not grow unboundedly."

**Why a Contradiction Journal?** The brief explicitly identifies contradiction
accumulation as the most common failure mode for this challenge. Rather than
silently overwriting conflicting beliefs, every correction is logged with full
context, giving direct, auditable proof of the agent's ability to recover from
wrong beliefs — one of the graded criteria for agent behavior.

**Why a safety-check layer on top of the LLM?** A 3B-parameter local model run
entirely on CPU does not reliably follow multi-step instructions (e.g. "prefer
unexplored exits"). Rather than relying purely on prompt engineering, a small
deterministic layer catches specific, well-understood failure patterns and
corrects the action before it reaches the game — while the LLM still makes the
primary decision every step.

## Known limitations

- The custom environment is intentionally small (5 rooms) to keep the scope
  tight and reliably demoable within the hackathon timeframe.
- The Extractor uses keyword/pattern matching rather than a general NLP
  pipeline — sufficient for this environment's vocabulary, per the brief's
  guidance that "the extractor does not need to be perfect."
- Small local models occasionally produce imperfect first-choice actions; the
  safety-check layer and the game's own feedback loop (e.g. "door is locked")
  allow the agent to recover within a few steps regardless.
